## 快速开始

服务由仓库根目录的 `docker compose` 托管，前端由 api 容器直接提供：

```bash
docker compose up -d db api
# 浏览器打开 http://localhost:8000
```

开发模式（改前端时）则 `cd ADG && npm run dev`，打开 http://localhost:3000
（dev 代理会把 `/api` 转发到 8000 的容器）。

第一次打开会问「你是谁？」——**这是认领记录的署名，没有密码**，
填一个能区分团队的称呼即可。

## 标注工作流程

整个流程围绕「**听 → 判 → 改 → 下一个**」循环，预标注来自 DiariZen，
人工只负责纠错：

1. **上传音频**：列表页「上传音频」，可多选（支持 MP3/WAV/M4A 等常见格式）。
   自动做流式去重、归一化成 16 kHz 单声道。
2. **拿预标注**，二选一：
   - 系统部署了 worker：上传后状态从「排队中」→「识别中」→「待标注」，约 1 倍实时；
   - 或本地/别处跑出了 RTTM：点该行「导入 RTTM」。文件名与录音对不上会要求确认，
     防导错污染测试集。
3. **认领并标注**：点「认领并标注」进入标注页（状态需为 待标注/标注中/已完成）。
   如果被同事认领着，强行接管时对方未保存的修改会丢，页面会先提示。
4. **逐段纠错**：`J` 从第一段开始，听 → 不对就改 → 下一个。每个修改自动保存。
5. **标记完成**：标注页右上「标记完成」→ 回到列表。
6. **导出**：列表页每行「RTTM」单个导出，或「导出全部已完成（zip）」。
   导出为**标准 10 字段 RTTM**，可直接喂 `md-eval.pl` / `dscore` 计算 DER。

## 列表页

- **状态**：待预标注 / 排队中 / 识别中 / 待标注 / 标注中 / 已完成 / 失败；
  失败会显示原因摘要。有排队/识别中的任务时列表每 10 秒自动刷新。
- **版本**：保存次数，用于判断「别人动过没有」。
- **删除**：连同音频和标注一起删，无回收站，确认框会二次提醒。
- **导出 RTTM**：随时可导，不要求完成。

## 标注页

### 顶部工具栏

返回列表｜录音名｜状态｜保存状态（未保存/已保存 vN）｜撤销/重做｜缩小/放大｜
保存｜标记完成｜导出 RTTM｜快捷键面板（`?`）。

缩放只影响视图，不动边界；缩放范围 10–1200 px/s。

### 时间轴

- 每说话人一条轨道，**共用同一根标尺**和滚动位置，跨说话人的重叠一眼可见。
- **拖动轨道空白处**：新建该说话人的片段。
- **点击片段**：选中；**拖动片段**：整体移动；**拖左右边缘**：调边界。
- 红色竖线是播放头，跨所有轨道；点波形任意处跳转。
- 片段内文字是其 `text`（保留给字幕阶段用，当前不参与导出）。

### 说话人面板

每行：色块｜数字键｜名称输入框｜已认领段数｜「合并到…」。

- **名称**：直接输入改名。`label`（如 `0`/`3`）是稳定主键，改名不影响任何数据，
  **不要为了改 label 去删人重画**。
- **＋ 新建说话人**（快捷键 `N`）：DiariZen 漏人时用。
  - 有选中片段 → 新建说话人并把这段拆给他（VBx 把两个人合并成一个标签时，这是首选修复）；
  - 没有选中片段 → 只新建一个空轨道，之后点该轨道空白画片段，或选中片段后按它的数字键改判。
  - 新说话人的数字键是「原人数 + 1」，弹提示会告诉你是几。
- **合并到…**：把该说话人的全部片段改判给对方并删除标签。
  合并后若同一人出现自重叠，重叠部分会被合并（有提示）——这是模型过分割的又一次修复，
  意思是「一个人要么在说话要么不在」。

### 常用操作技巧

- 走查：`J`/`K`（或方向键）逐段移动并试听，段尾自动停。
- 改判：选中后按 `1`–`9`；多于 9 人时必走的路径是 `N` 新建 + 数字键。
- 拆分：播放头停在切开处，选中片段按 `S`。
- 合并：选中前一段，`M` 吞掉同说话人的下一段（空隙也吞——DiariZen 爱在停顿处断段）。
- 边界吸附播放头：`[`（起点）/`]`（终点）；微调起点 `L`/`;`、终点 `,`/`.`（Shift 为 100ms）。
- 删除片段 `Del`/`Backspace`；撤销 `Ctrl+Z` / 重做 `Ctrl+Shift+Z`（连续微调算一步）。

## 快捷键

面板里按 `?` 打开完整清单，这里同步一份：

| 分类 | 键 | 功能 |
|---|---|---|
| 播放 | 空格 | 播放 / 暂停 |
| 播放 | Enter | 重听当前片段 |
| 播放 | ← → | 后退/前进 1 秒（⇧ 为 5 秒） |
| 播放 | - = | 降低/提高倍速 |
| 走查 | J ↓ | 下一段并试听 |
| 走查 | K ↑ | 上一段并试听 |
| 走查 | Esc | 取消选中 |
| 修改 | 1–9 | 把选中片段改判给第 N 位说话人 |
| 修改 | **N** | **新建说话人**（选中时把这片段拆给他） |
| 修改 | S | 在播放头处拆分 |
| 修改 | M | 与同一说话人的下一段合并 |
| 修改 | Del | 删除片段 |
| 边界 | [ | 起点吸附到播放头 |
| 边界 | ] | 终点吸附到播放头 |
| 边界 | L ; | 起点微调 ∓10ms（⇧ 为 100ms） |
| 边界 | , . | 终点微调 ∓10ms（⇧ 为 100ms） |
| 其他 | Ctrl Z / Ctrl ⇧ Z | 撤销 / 重做 |
| 其他 | Ctrl S | 立即保存 |
| 其他 | ? | 打开快捷键面板 |

灰色条目（面板里）表示需要先选中片段。**在输入框里打字时快捷键不生效**。
`Tab` 是浏览器焦点键，特意不与任何功能冲突。

## 常见问题

**Q: 数据存在哪？关浏览器会丢吗？**
A: 服务端 Postgres + 音频卷。关浏览器/换机器不会丢，
但**服务端在备份之前仍可能整体丢失**——请运维定期跑 `sh server/scripts/backup.sh`。

**Q: 两个人同时标一个文件？**
A: 认领机制默认不允许；强行接管会丢对方的未保存修改。
保存时若版本已过期会弹「有人先保存了」，点重载后再改。

**Q: 预标注跑错了/算错了，能重新跑吗？**
A: 不能从界面重跑；可以把当前标注清成目标状态后「导入 RTTM」覆盖。
（这就是 DiariZen 重跑的价值：label 稳定、可比。）

**Q: 一个说话人在文件中间才出现，最前面没他？**
A: 走到他的第一段，`N` 把他拆出去；然后选他其余片段按他的数字键改判即可。

**Q: 能不能多选片段一起操作？**
A: 现在只有单选（这是比「改判」单价更低的交互，若多人常多选改判，值得加一组）。
一次一选：选中 → 数字键 → 下一个。
