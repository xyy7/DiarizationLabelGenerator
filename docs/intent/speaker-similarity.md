# 说话人稳定音频与声纹相似度改判 意图书

**日期**：2026-08-29
**状态**：意图已确认，尚未进入方案设计
**产生方式**：`interview-me` 访谈 + 既有系统代码核对
**关联**：[adg-refactor.md](./adg-refactor.md) —— 本功能是既有"客户端–服务端纠错式标注系统"的一个子功能

> 本文只记录**要什么、为什么**，不记录**怎么做**。

## 一、确认的意图

### 产出物

在标注系统（单录音文件内）新增两件事：

1. **稳定音频**：标注员可把任何已标注片段标记为该说话人的"稳定音频"
   （访谈确认每说话人**几段即可**，建议 2~5 段、单段 ≥2s 为宜），作为该说话人的参考声纹。
2. **声纹相似度面板**：右键任一段 → 菜单里"自动识别" → 弹出面板按相似度序显示各说话人；
   每行 = 一个说话人，行内列出它的各段稳定音频（各自可试听 + 相似度 %）；
   勾选一个或多个说话人后确认，该段**改判**给被勾选的说话人。
   **勾多个 = 这段同时属于多个说话人（重叠说话）**，导出 RTTM 时多说话人段表达正确。

意图层面已确认：**一段标注可以同时属于多个说话人**。
现 DB `segments.speaker_label` 为单值，重叠的存储形态
（两段同时间不同 speaker / 一段对多人）是方案设计问题，本文不做预设。

### 使用者

标注员本人及团队成员（沿用现有系统）。内部生产工具。

### 为什么是现在

纠错式工作流（DiariZen 预标注 → 人工修正）中「听→判→改」是主操作；
改判正确性依赖人耳比对，声纹相似度把候选缩小成一个可试听的序列表，
把"在整条波形里找对照"变成"看分数、听几秒、选一个人"。

### 成功的样子

- 任一段疑似标注错误，"右键 → 识别 → 试听 → 勾选 → 确认"数秒内完成
- 双人同时说话的段可正确标注为多说话人，导出标准 RTTM，
  md-eval / dscore 正常计算 DER 不出错
- 相似度计算在服务端容器完成；CPU 机器可跑，GPU 机器自动用 GPU

### 约束

| 约束 | 影响 |
|---|---|
| 模型：`iic/speech_eres2net_sv_zh-cn_16k-common`（ERes2Net-Huge，约 55M 参数，192 维 embedding，16k / 80 维 mel；CPU 下 ONNX RTF ≈ 0.42，即 3s 音频全流程约 2.4× 实时） | CPU 容器可跑，无需 GPU；可直接嵌入「同步 API 请求内算一段 embedding」，也可批算 |
| 交互时效 | 点击"自动识别"后期望 **1~3 秒级出结果**：稳定音频的 embedding 预计算缓存，仅被识别的那一段现算 |
| GPU | **配置项**：服务/worker 检测到 GPU 自动使用 CUDA；无 GPU 回退 CPU。镜像构建需同时覆盖 CUDA 与 CPU 目标 |
| 作用域 | 稳定音频与相似度仅在**单录音文件内**有效；不引入跨文件人物实体 |

### 明确不做

- 跨文件全局说话人身份（访谈确认：版本 B）
- 浏览器内推理
- "两个 spk 其实是同一个人"的说话人合并独立操作（面板能辅助这种判断，但不作为本功能动作）
- 稳定音频自动挑选（先人工标定）
- 字幕相关工作（沿用第二阶段约定）

## 二、访谈中确认 / 调整的判断

| 判断点 | 结论 |
|---|---|
| 稳定音频跟"真人"跨文件（版本 A）还是仅单文件内（版本 B） | **版本 B**：仅文件内。换录音重挑稳定段，不需要新的人物实体 |
| 勾选多个说话人的语义 | **整段时间同时属于多个说话人（重叠，版本 A）**；不做按时间自动切开。理由：重叠段内分界点人耳没有正确答案；重叠恰是 diarization 评测最在意的区域 |
| 面板是否包含当前说话人自身稳定音频 | **包含**：若自己排第一，说明原标可能没错（防误杀） |
| 未设稳定音频的说话人 | 不参与相似度排序；在面板中单独列出（无分数项） |
| GPU | **做成配置项**：自动检测，无 GPU 回退 CPU |
| 模型选择 | 用户指定 eres2net；备选记录：ERes2NetV2（17.8M，RTF 0.142，短语音更强）——被选中也无需改意图 |
