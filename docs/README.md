# docs/ — 项目说明与设计文档（入 git）

技术方案的源头。按类型分目录：

| 位置 | 内容 | 上游 |
|---|---|---|
| `intent/` | 意图书：**要什么、为什么**（用户访谈产生） | — |
| `spec/` | 技术方案：**怎么做**（决策依据，落地到意图） | `intent/` |
| `ARCHITECTURE.md` | 系统架构总览：组件关系、逻辑架构图、三种部署形态（docker / 本地 conda / AutoDL） | 全部 |
| `HANDOFF.md` | 交接文档：已完成什么、验证到什么程度、还欠什么 | 全部 |

下游（**不入 git**）：

- `tasks/`（仓库根）——任务拆分/记录，按 `YYYY-MM-DD/` 分文件夹
- `tests/`（仓库根）——手工测试样例数据

约定：`intent/` 只记意图不记方案；`spec/` 每节给出决策与依据；
任务完成后先就地更新本文档对应说明，再在 `tasks/` 补次日期的任务记录。
